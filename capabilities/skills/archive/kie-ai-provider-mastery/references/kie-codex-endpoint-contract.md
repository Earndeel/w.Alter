# Kie.ai Codex/Responses contract discovery

Use this reference for any Kie model documented on `/codex/v1/responses`, especially when the public page is generated by Apidog and the readable extractor omits nested schemas.

## Procedure

1. **Resolve the model on the matching catalog.** Query `GET https://api.kie.ai/codex/v1/models` with `Authorization: Bearer <key>` and a recent Chrome `User-Agent`. Record the exact `id`; do not infer it from a marketing slug or from the generic `/v1/models` route.
2. **Read the official model page first.** Use `walter_browse` on the Kie docs URL. Capture the endpoint, headers, required fields, response media type, and documented enum values before designing a payload.
3. **Recover the structured schema when the page text is incomplete.** The Apidog page may embed a serialized `window.__remixContext.streamController.enqueue("...")` payload. Fetch only the official page, decode the outer JavaScript string, parse the inner JSON array, then resolve its indexed object/string references. Inspect `loaderData.root.docsDataState.resourceData.data.requestBody.jsonSchema`, `extraData.dataSchemaDefinitions`, and `responses`; never fill an unresolved `$ref` from memory.
4. **Separate documented, UI-only, and inferred fields.** A playground switch is not automatically an API parameter. A marketing capability is not a wire-level tool. Keep absent fields (`max_output_tokens`, `temperature`, `response_format`, and similar) explicitly unverified rather than silently adding them.
5. **Reconcile contradictions explicitly.** Check for stale examples whose model ID disagrees with the enum, prose defaults that disagree with JSON Schema, and a streaming response declaration that conflicts with `stream: false`. Send disputed controls explicitly and parse the actual response headers/events.
6. **Verify in two stages.** A catalog `200` proves model visibility and authentication. A valid POST is the separate inference test and may be billable; do not run it merely to complete a schema review without approval. If a non-generative probe returns a provider maintenance/server error, report that exact live observation and do not upgrade it to “generation works.”

## Contract notes to record

For each model, preserve:

- method and full URL;
- required headers and whether a browser-shaped `User-Agent` is needed;
- top-level request fields, types, requiredness, defaults, and allowed values;
- nested input item schemas and unresolved references;
- tool families and mutual exclusions;
- streaming event names, terminal marker, and non-stream response shape;
- usage/credit fields and documented error envelopes;
- unsupported or merely UI-visible controls;
- live catalog result and any separate paid smoke-test result.

Do not claim compatibility with the full OpenAI Responses API unless the target Kie page and a controlled live probe establish it. Preserve raw/redacted evidence when debugging Hermes routing or billing.
