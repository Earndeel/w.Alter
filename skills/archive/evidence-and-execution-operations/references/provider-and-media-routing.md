# Provider and media routing depth

Use these gates after the umbrella's approval and evidence rules have fixed the target and permitted side effects.

## Route and contract gate

1. Resolve the exact, case-sensitive model ID, provider, endpoint, API mode, region, account, credential scope, entitlement, quota, modality, inputs, output contract, and budget.
2. Check the official catalog and supported route, then inspect the active profile's enabled tools, current session schema, model-resolution logic, request builder, and actual outbound model ID. Configuration, authentication, and catalog presence are separate from in-session callability.
3. Classify controls as call-time arguments, configuration-only choices, or fixed payload fields. Use the smallest authenticated probe through the intended client before a billable job; do not change production routing to answer a catalog question.
4. On failure, distinguish validation, not-found, access, throttling, transport, provider execution, local tracking, and artifact errors. Preserve the original job ID and poll it after interruption rather than creating a duplicate.

## Evaluation gate

Normalize prompt, source files, system instructions, tools, permissions, timeout, iteration cap, and rubric across providers. Record latency, tokens, cost, errors, successful-task rate, artifact quality, and unverified values separately. Keep provider-aborted runs distinct from local or recipient failures.

## Media release gate

Bind real source bytes or provider handles and retain hashes, dimensions, prompts, job/output IDs, and stage state. Download the result and run metadata checks plus a full decode; review visual, audio, caption, duration, resolution, copy, and brief compliance. Keep the clean master separate from versioned derivatives, and treat upload, a stable URL, or a task-success label as transport evidence rather than delivery proof.

## Browser-driven generation

Treat the provider's rewritten plan and cost confirmation as the production contract: verify scene order, dialogue, wardrobe, duration, aspect ratio, model mode, ingredients, and no-text requirements before approving spend. Attach ingredients to the message that will be planned, select only the newest non-stale approval row, and re-check the composer after policy dialogs or refusals. Resolve the generated asset from its actual new media identifier rather than a thumbnail, keep signed URLs out of logs, and validate the fetched bytes with metadata and full decode. If an editor no-ops or a duration cap blocks the brief, generate missing scenes through the supported route and assemble locally, then run the same final QA gates.
