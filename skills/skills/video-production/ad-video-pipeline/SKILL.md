# Ad Video Pipeline — Modular Architecture

**Purpose:** Reverse-engineer viral videos from foreplay.co, analyze them shot-by-shot, adapt for cosmetic/beauty target audience, and regenerate via Kling V3 Pro.

## Audio contract — prerequisite for prompts and delegation

- Resolve the requested audio source before preparing any generation or subagent brief. A requirement for audio generated natively by the video model forbids a separate TTS voice, overdubbing, or externally synthesized music; an audio stream muxed into the final video does not establish native provenance.
- Put the exact approved dialogue and the native-audio requirement in each speaking shot's generation prompt and supported provider settings. Remove contradictory negatives such as `no audio`, `no speech` or `VO added in post`; do not assume native-audio support from the model name or an audio stream alone.
- Keep visible speakers' original synchronized image and sound paired through edits. Time captions against the actual generated dialogue, not a substitute TTS transcript; verify native source provenance, exact spoken wording, lip-sync and intelligibility before accepting a shot.
- When an audio-source correction supersedes an existing brief, invalidate conflicting prompts and downstream audio artifacts for delivery, preserve them as history, and propagate the corrected contract to all delegates. Distinguish preserved identity references from usable dialogue takes, and obtain fresh approval before paid regenerations when the existing approval forbids them.

## Architecture (6 Modules)

```
Notion Kanban → VIDEO SCOUT → VIDEO ANALYZER → PROMPT ENGINEER
                                                      ↓
                                                  REVIEW (Lucas)
                                                      ↓
                                            GENERATOR → DELIVERY (Drive)
```

### Module 1: VIDEO SCOUT
- Takes a foreplay.co (or any video) URL from Notion
- Downloads the video with yt-dlp or ffmpeg (may need Webtop/CDP for anti-bot on foreplay.co)
- Runs `ffmpeg -i video.mp4 -vf "select='gt(scene,0.3)'" -vsync vframes shots/shot_%04d.jpg` for shot detection
- Extracts keyframes per shot: `ffmpeg -ss {timestamp} -i video.mp4 -vframes 1 -q:v 2 shots/keyframe_%04d.jpg`
- Measures: total duration, fps, aspect ratio, count of shots
- Output: `output/{video_id}/` with `shots/`, `meta.json`, `source_video.mp4`

### Module 2: VIDEO ANALYZER (V3 — Direct Video Input, NO FRAMES)
- Sends the full `.mp4` as base64 to OpenRouter with `qwen/qwen3.6-plus:free`
- LLM decomposes the video itself (no frame extraction needed)
  - **Shot-by-shot description**: framing, camera, lighting, subjects, text overlays
  - **Scores**: qualite, engagement, vente, global (1-10)
  - **Structure**: timestamps, shot types, transitions
  - **Recommendations**: what works, what to improve for Kling regeneration
- Videos >150MB auto-compressed: `ffmpeg -vf scale=720:1280 -crf 28`
- 5-retry exponential backoff on 429 (30/60/90/120/150s pauses), 180s timeout
- Output: structured text in `video_analysis` table (JSON scores + detailed analysis)
- Script: `modules/video_analyzer_v3.py` (replaces `video_analyzer.py`)

### Module 3: PROMPT ENGINEER — LLM-based Payload Generation (Multi-Model)

**HOW IT WORKS (V5 — April 2026, MULTI-MODEL):**
The payload is generated by the LLM (OpenRouter, `google/gemini-3-flash-preview`, temperature=0.1). Each video model has its own config directory with a preprompt + schema. The system is generic — Fal.ai is the unique provider, only the endpoint + prompt template + schema change per model.

#### Architecture: Model Registry

```
models/
  kling_v3/
    config.json    ← id, name, provider, modes (t2v/i2v), endpoints, params
    prompt.md      ← LLM preprompt (rules, decoupage, style constraints)
    - `kling_v3/schema.md` — API schema reference (markdown, NOT JSON — just text for LLM)
  runway_gen4/     ← add new models by creating a directory
    config.json
    prompt.md
    schema.md
```

**To add a new model:**
1. Create `models/<model_id>/` with `config.json`, `prompt.md`, `schema.json`
2. Dashboard auto-detects it via `GET /api/models`
3. Model appears in the dropdown selector

#### config.json format (SIMPLIFIED — final version):
```json
{
  "name": "Kling v3 Pro",
  "endpoint": "fal-ai/kling-video/v3/pro/text-to-video"
}
```
The `id` comes from the **directory name** (`models/kling_v3/`), NOT from config.json. `model_runner.list_models()` injects `cfg['id'] = name` at runtime. Only 2 fields the code uses: `name` (display) and `endpoint` (Fal.ai endpoint). No modes, no provider, no env_key — keep it minimal.

#### Core Module: `modules/model_runner.py`

Generic runner that loads any model config and handles generate/submit/sync:

```python
model_runner.py list                          # List all available models
model_runner.py generate --card_id 15 --model kling_v3  # Generate payload via LLM
model_runner.py submit --card_id 15 --model kling_v3    # Submit to fal.ai
model_runner.py sync --card_id 15                       # Sync job status
model_runner.py sync-all                                # Sync all active jobs
```

Internal flow:
1. `load_model(model_id)` → loads config + prompt + schema from `models/<id>/`
2. `get_card_context(card_id)` → loads analysis + comments from DB
3. `call_llm(preprompt, user_section)` → sends 4 sources to LLM, returns JSON
4. `submit(card_id)` → calls `fal_client.submit(endpoint, args)` using payload
5. `sync(card_id)` → polls `fal_client.status()` → saves result

#### Preprompt Modal (Multi-tab Dashboard UI):
The dashboard Preprompt button now opens a multi-tab modal managing ALL static prompts:
- Tab 1: **Video Analysis** → `prompts/video_analysis_prompt.md`
- Tab 2: **Kling API Schema** → `prompts/kling_api_schema.json`
- Tab 3: **Kling Prompt** → `prompts/kling_prompt.md`

Each tab has its own textarea + Save button. Frontend polls the LLM generation every 4s for up to 400s.

#### Prompt Files (`prompts/` directory):
- `video_analysis_prompt.md` — System prompt for video analysis (LLM decomposes video → JSON)
- `kling_api_schema.json` — Kling v3 API documentation with embedded `{...}` JSON example for default params
- `kling_prompt.md` — Rules for Kling payload generation: decoupage max 15s, product swap, audio logic, female-only casting, multi_prompt vs prompt logic
- `README.md` — Documentation of each file

#### LLM Generation Details:
- Model: `qwen/qwen3.6-plus:free` via OpenRouter
- Temperature: **0.1** (deterministic output)
- Max tokens: 8000
- Timeout: **180s** per attempt
- Retries: **5** with exponential backoff (30s, 60s, 90s, 120s, 150s for 429 rate limits)
- Total worst case: ~600s (10 min) if heavily rate-limited
- Response is stripped of markdown code blocks, parsed as JSON
- Payload is auto-saved to `video_analysis.kling_payloads` in DB

#### Kling Rules (enforced by LLM via preprompt):
1. **Decoupage**: max 15s per payload. Video > 15s = split into multiple payloads
2. **Product Swap**: If video shows a product, replace it with client's product from comments
3. **Audio**: `generate_audio: true` ONLY if lip-sync/narration + client provided text in comments
4. **Multi-prompt**: Multiple cuts → `prompt: null` + `multi_prompt: [{"prompt":..., "duration":...}]`
5. **Visual only**: No metadata ("Scene 1:", "Camera:"). Describe what you see fluently
6. **Female-only casting**: Add "male, men, masculine, boy" to neg_prompt; describe only women
7. **cfg_scale**: 0.5-1.0 max (v3 constraint)

#### Async Pattern (CRITICAL):
Flask sync endpoints TIMEOUT waiting for LLM (Gunicorn/WSGI thread blocked).
Pattern: POST returns task_id immediately → frontend polls GET `/api/kling/generate/status/<task_id>` every 4s.
Background thread runs the LLM call. In-memory `_generate_tasks` dict tracks state.
If Flask restarts, pending tasks are lost but payload is saved to DB after completion.

### Module 4: REVIEW
- Presents the proposed Kling payload to Lucas
- Shows: original keyframes side-by-side with proposed prompts
- Lucas approves or requests modifications
- Modifications can target: specific shot prompts, duration, aspect ratio, mood
- Output: approved `kling_payload.json`

### Module 5: GENERATOR
- Takes approved payload
- If `@Element` references needed → generates reference images via Nano Banana 2 (`fal-ai/nano-banana-2`)
- Submits to Kling V3 Pro via fal.ai API:
  - `text-to-video Pro`: `mcporter call fal.generate_video model="kling-video/v3/pro/text-to-video" arguments={...}`
  - `image-to-video Pro`: for product-consistent shots
  - `image-to-video Standard`: `mcporter call fal.generate_video model="kling-video/v3/standard/image-to-video" arguments={...}`
- Polls until complete, downloads resulting MP4
- Output: `output/{video_id}/final.mp4`

### Module 6: DELIVERY
- Creates client subfolder in Google Drive
- Uploads final video: use Google Drive SDK with `MediaFileUpload`
- Updates Notion card status to "Livrée"
- Notifies Lucas with download/share link

**Step 3: Parse Card Properties and Comments from Text**
Notion renders card properties as "Label\nValue" pairs in the page text. The section headers are:
- Properties: `Persona`, `Angle Marketing`, `Statut`, `Brief Owner`, etc.
- Comments: Look for the `Commentaires` header followed by content until `Utilisez Notion` (language popup)

```python
def extract_comments(full_text):
    comments = []
    lines = full_text.split('\n')
    in_comments = False
    for line in lines:
        stripped = line.strip()
        if stripped == 'Commentaires':
            in_comments = True
            continue
        if in_comments:
            if 'Utilisez Notion' in stripped:
                break
            if stripped:
                comments.append(stripped)
    return comments
```

Navigate to the parent page URL, scroll iteratively, then extract:

**Solution B: Google Drive (authenticated session via CDP cookies)**

Google Drive uses a YouTube embed for video preview (cross-origin iframe). `document.querySelector('video').currentSrc` does NOT work. Standard tools (`yt-dlp`, `gdown`) return HTTP 403 on restricted files.

Working method: Export authenticated browser cookies via CDP → use `curl -b` with the direct download endpoint.

Step 1 — Export ALL cookies from the CDP session:
```python
import urllib.request, json, websocket

# Connect to an active Drive tab
resp = urllib.request.urlopen('http://localhost:9222/json/list')
tabs = json.loads(resp.read())
drive_tab = next((t for t in tabs if 'drive.google.com' in t.get('url', '')), None)
if not drive_tab:
    raise Exception('No Drive tab found')

ws = websocket.create_connection(drive_tab['webSocketDebuggerUrl'], timeout=30)

# Get all cookies via CDP
ws.send(json.dumps({'id': 2, 'method': 'Network.getAllCookies', 'params': {}}))
r = json.loads(ws.recv())
all_cookies = r.get('result', {}).get('cookies', [])

# Write Netscape format cookie file
lines = ['# Netscape HTTP Cookie File']
for c in all_cookies:
    domain = c.get('domain', '')
    include_sub = 'TRUE' if domain.startswith('.') else 'FALSE'
    path = c.get('path', '/')
    secure = 'TRUE' if c.get('secure', False) else 'FALSE'
    expiry = str(int(c.get('expirationDate', 9999999999)))
    lines.append('\t'.join([domain, include_sub, path, secure, expiry, c['name'], c['value']]))

with open('/tmp/google_cookies.txt', 'w') as f:
    f.write('\n'.join(lines))
```

Step 2 — Download via curl with cookies:

## Pipeline Database (SQLite)

### Kling v3 cfg_scale Constraint (VALIDATED April 2026)

**CRITICAL: `cfg_scale` must be ≤ 1.0 on ALL Kling v3 endpoints** (both `standard` and `pro`).

- `fal_client.submit()` accepts any value and returns a `request_id`
- But `fal_client.result()` fails with `422`: `'cfg_scale', 'msg': 'Input should be less than or equal to 1', 'input': 4.5`
- The endpoint validates the payload after queue submission, so the error only appears on retrieval
- **Solution**: Always use `cfg_scale: 1.0` (max) or lower (typical range: 0.5-1.0)
- `cfg_scale: 0.5` → permissive, Kling follows its own style
- `cfg_scale: 1.0` → strictest allowed, follows prompt most closely

**Working endpoint**: `fal-ai/kling-video/v3/standard/text-to-video` with `cfg_scale: 1` — tested and produces 12s multi_prompt videos (~12MB output).

**Key difference between standard and pro**: `pro` does NOT accept higher cfg_scale values. The validation is identical. Use `standard` unless you need a specific `pro`-only feature (check OpenAPI schema for differences).

### OpenRouter Rate Limit (Kling Payload Generation)
- The Kling payload LLM call takes ~90-120s for the first response
- OpenRouter returns **429** rapidly if calls are too frequent
- The 5-retry backoff (30/60/90/120/150s) is NOT sufficient for rapid successive calls
- **If you just ran a video analysis, wait 2-3 min before calling Kling payload gen**
- The async Flask pattern (task_id + polling) prevents HTTP timeout but the LLM call can still fail with 429 after all retries
- If `status=failed` with "Rate limit 429", simply retry after 2 minutes

### mcporter Bash Gotcha
Parentheses `()` in mcporter arguments cause `bash: syntax error near unexpected token '('`. Always use `--category` and `--search` flags instead: `mcporter call fal.list_models --category video --search "kling v3 pro"` — OR escape with `\(` `\)` if function-style args are needed.

### Multi-Model Refactor Pitfalls (V5, April 2026)

**Don't over-abstract the provider layer.** When Lucas says "multiple models," he means different preprompts + schemas going through the SAME provider (Fal.ai). Don't assume you need provider adapters (Replicate, direct API, etc.) — ask first.

**DB migration: check actual column names.** The `ALTER TABLE ADD COLUMN` succeeded but the `UPDATE ... SET` referenced `kling_error` which didn't exist in the actual schema (only in the skill doc). Always run `PRAGMA table_info(table)` before writing migration SQL.

**COALESCE for column migration:** When adding generic columns alongside legacy ones, use `COALESCE(new_col, old_col)` in reads and `UPDATE SET new_col = COALESCE(new_col, old_col)` for migration. This ensures both old and new data paths work during transition.

**Dashboard JS: rename elements consistently.** When renaming `kling-payload` → `gen-payload`, update ALL references: the textarea id, the JS functions that read it, and the CSS if any. A missed reference breaks the page silently (JS error in console, dashboard stuck on loading).
