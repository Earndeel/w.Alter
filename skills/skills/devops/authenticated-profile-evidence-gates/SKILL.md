# Authenticated profile evidence gates

Load the service/browser and sealed-login skills first. Treat account existence, authenticated access, freelancer-profile existence, local drafting, site saving and publication as separate states, each needing its own evidence.

A named `walter-browser` session is not automatically Hermes' native browser target. If sealed fill refuses with `page origin None`, check the native target once. When no usable tab is bound, report the bridge mismatch and stop only authentication. Do not infer a missing password, reveal or manually type a saved secret, spoof the origin, mutate adapter globals or repair infrastructure outside authorization.

Before reusing a portfolio template, inspect its actual assets and testimonial constants. Placeholder-image services and unsupported named testimonials are not evidence of completed client work. Conflicting CV dates or qualification wording must be omitted or resolved; a polished generated CV is not independent corroboration.

Existing video filenames alone do not establish authorship, client results or permission to publish. Use service-positioning language for supported capabilities without converting project discussions into paid delivery or formal employment claims.

For read-only Google CLI calls, account for diagnostic warnings before JSON and validate the parsed schema. Print narrow factual excerpts, not full mail containing reset links, authorization links, tokens or codes.

When access remains blocked, deliver a real local draft and evidence report with exact blockers, source references, untouched fields, browser/session identifiers and explicit saved=false/published=false. A successful file write is not a site publication.
